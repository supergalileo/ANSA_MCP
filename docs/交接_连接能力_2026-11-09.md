## 一、为什么要做这件事

上一阶段交付的是 **402 个互相独立的零件级网格**。它们：

- 节点不共享（每件单独 `base.Open` 一个新库）
- 零件之间没有任何连接单元
- 因此**无法直接提交整车求解**——一跑就散架（无约束的刚体模态）

这是当前能力和「能算整车」之间唯一的关键缺口。补齐它，工具链才从「零件级」升到「总成级」。

**目标定义（先对齐，别急着写代码）**：给定 402 个已交付的 `.ansa` 和一套连接位置数据，产出一份**可提交求解**的整车模型，其中：

1. 所有零件被搬进同一个库里、按装配位置摆好
2. 每个焊点/胶接位置都有对应的连接单元
3. 连接单元的两端节点实实在在挂在两层壳上（不是悬空）
4. 导出 `.nas` 后能用求解器跑通，刚体模态数 = 6

第 4 条是验收标准。前三条都可能"看起来成功"而实际不通。

#### 2.3.2 问题 1：里面装的是什么实体？→ **封闭实体，点焊球为主**

| 未标注（路径只有 `Body.N` / `OPEN_SHELL #nnnn`） | 3 869 | 绝大多数是 8×8×8 mm 的球，无法从命名判类型 |
| `SPOTWELD_2T` | 1 518 | 8×8×8 mm，4 面 |
| `SPOTWELD_3T` | 773 | 8×8×8 mm，4 面（与 2T 尺寸完全相同） |
| `RIVET` | 326 | 8×8 mm |

| `LASER` | 166 | 4×54×4 mm 细长条，集中在 R010 |
| `FOAM` | 42 | 块状，在 R001 里 |
| `FILLET` | 30 | |
| `SEAM` | 5 | |
| `SPOTWELD_4T` | 3 | 10×10×10 mm |

**5 780 个是"球状"实体**（面数 ≤8、尺寸 6–12 mm），这就是点焊/铆钉的可视化几何。

**关键发现：点焊球是实心几何体，不是 CAD 特征。**

#### 2.3.5 最要命的一条：零件号体系不重合

路径里确实带零件号，格式是 `<母件>_WELD.N\<被焊件>W.N\SPOTWELD_2T.N\MANIFOLD_SOLID_BREP #nnn`，
例如 `A0072600494_WELD.10\A0072600518_WELD.3\A0072600518_WELD_1.5\SPOTWELD_2T.15`。

**但把这些号拿去对 540 目标件：**

| 指标 | 数值 |
|---|---|
| 13 件路径里出现的零件号并集 | 115 个 |
| 其中出现在 540 目标件里的 | **2 个**（`A0072601106W`、`A0072600874W`） |
| 3 325 个带路径的连接实体中，号能对上的 | **8 个（0.2%）** |
| 540 目标件被连接件覆盖到的 | **2 / 101** 个唯一零件号 |

540 目标件的号段是 `A007S*`（118 件）、`A00726*`（59 件）、`A00721*`（9 件）、`A00723*`（5 件，玻璃）；
连接件引用的号是 `A0072600001`、`A0072600234`、`A0072600592` 这类**另一批** A00726 号。

**这不是命名不规范，是数据来自另一套 CAD 结构（另一个层级的装配树）。**

#### 2.3.6 纯几何路线也堵了

5840 个球状实体按中心点做包围盒归属（容差 1.5 mm）：

| 落在几个目标件包围盒里 | 数量 | 占比 |
|---|---|---|
| 0 个 | 67 | 1.2% |
| 1 个 | 127 | 2.2% |
| 2 个 | 700 | 12.1% |
| **3 个及以上** | **4 886** | **84.5%** |

包围盒重叠是车身结构常态（长条形件横跨半车），所以"命中 2 个"根本不能当成"这个焊点连的就是这两个件"。
**路线 A 在真实数据上的可靠性已经实测出来了：不可用。**

3. **降级交付**：如果拿不到映射，就只能做「整车装配 + 全局 tie/绑定」的近似模型，

## 三、技术路线（三条路，建议按顺序试）

> **2026-11-10 更新**：`ansa.connections` 模块 60 个函数的 API 已调研完毕，
> 见 `连接能力_API调研_2026-11-10.md`。**路线 C 可行**，且核心是
> `AutoSetConnectivityInConnections`（自动挂零件）+ `RealizeConnections`（转 FE）。
> 下面三条路的判断基于 11-09 时的信息，保留作为背景。

### 路线 A：几何最近邻自动连接 —— 最快出结果，最不可靠

**做法**：焊接球体的中心坐标 → 在每个球体半径 R 内的所有壳单元节点里，找属于两个不同零件的最近节点对 → 建 `RBE3` 或 `CWELD`。

**优点**：不需要连接清单，纯几何，一天能写出原型。

**致命问题（必须承认）**：
- 相邻但**不连接**的零件会被误连（例如间隙 0.5 mm 的两块板）
- 搭接区（三层板）判定不了哪两层是一对
- 容差 R 是全模型一个常数，但实际间隙分布很宽
- **错误连接比没有连接更糟**：模型看着能跑，刚度是错的，而且没人会发现

**适用场景**：只有几何、没有清单，且只做趋势分析（模态频率量级、传力路径）。
**不适用于**：任何要出报告的强度/刚度分析。

### 路线 B：读连接清单 + 坐标匹配 —— 推荐的中间态

**前提**：2.3 的第 3 个问题答案是「有表格」。

**做法**：
```
连接清单.csv（点号, 坐标xyz, 零件1, 零件2, 类型）
   ↓
脚本读取 → 按坐标在 402 个网格里做最近搜索
   ↓
找到零件1 上的节点 A、零件2 上的节点 B（距离 < tol）
   ↓
建 RBE3(A 主节点, B 从节点集) 或 CWELD
   ↓
记录：匹配成功的点数 / 未匹配点数 / 距离分布
```

**关键设计点**：
- **必须输出匹配报告**：每个焊点的实际间距、用了哪两个节点、是否超过容差。
  4240 个焊点里如果有 200 个间距 > 3 mm，说明零件位置对不上，先解决几何问题。
- **不要静默补**：匹配不到就报出来，不要"就近连一个"。
- 三层板：一个点要连三对，清单里应有 3 行。

### 路线 C：用 ANSA 自带连接功能 —— 最靠谱但要逆向 API

**思路**：ANSA 的 `Deck > Connections` 模块本身就有完整能力（Spotwelds、Seam welds、Adhesive、Bolts），
GUI 上做的东西背后都是 Python API。

**要先摸清的 API**（`ansa_api_search` 查，或直接 `dir()`）：
- `connections` 模块是否存在（`from ansa import connections`）
- `base.CollectEntities(deck, None, "CONNECTIONS")` 返回什么
- 焊接单元的卡类型：NASTRAN deck 下是 `CWELD` / `CROD` / `RBE3`？

**风险**：`ansa-api-verified.md` 里没有任何 connections 的记录，等于从零开始。
建议先花半天做**只读勘察**：打开一个手工做过连接的 ANSA 库，用
`base.CollectEntities` + `ent.card_fields(deck)` 把所有实体类型列一遍，看清楚 ANSA 是怎么存的。

**优点**：一旦走通，连接质量就是 ANSA 官方水平，不用自己调容差。
**缺点**：如果 connections 模块在 batch 模式下不可用（很可能），就得退回 A/B。

### 我的判断（2026-11-09 勘察后修订）

**原判断「先花半天勘察，再决定走 B 还是 C」——勘察已完成（见 2.3），结论是三条路都不通。**

修订后的判断：

- **路线 B 的"清单"不存在** → 需要向数据方要，是要不要继续做的前置条件
- **路线 A 已实测不可用**（84.5% 的球落在 3 个以上包围盒里）
- **路线 C 仍值得试**，但它解决的是"怎么建单元"，不是"连哪两个件"

**当前真正的卡点是数据，不是算法。** 建议动作：

1. 先向数据方确认：13 个 R 件的零件号体系为什么和 540 目标件不是一套？有没有对应关系表？
2. 拿不到映射表，就退回「8 个可精确连接的实体做成原型 + 全量降级为 tie 近似」，
   并且在报告首页写死近似性质。
3. 路线 C 的勘察（`connections` 模块 API）可以并行做，因为无论数据怎么来，最后都要建单元。

## 四、必须先想清楚的五个坑

### 坑 1：零件坐标怎么对齐 —— 已降级

402 个 `.ansa` 是**各自从 CATPart 单独导入**的。**已在 2026-11-09 实测验证：CATPart 单独
`base.Open` 保留 CATIA 绝对坐标，540 个件和 13 个连接件落在同一坐标系内，没有堆在原点。**

剩下的风险只剩一条：如果 402 个已交付网格在导出时做过平移/旋转，那批 `.ansa` 的坐标可能
和 CATPart 不一致。**组装前必须抽样 3 件，比对 `.ansa` 里的 `BoundBox` 与 `target_bbox.json`
对应件是否一致**，这个比原来的"两个零件相邻"验证更直接。

### 坑 2：单元规模会翻几倍

402 件 = 174 万壳单元。搬进一个库以后：
- 内存：单库 174 万单元，ANSA 大约要 3–6 GB（估算，未实测）
- 导出 `.nas`：可能 2–3 GB 文本
- 求解：这个规模必须上集群

**先在 10 件零件的子集上验证全流程**，不要一上来就整车。

### 坑 3：`RBE3` vs `CWELD` vs `CROD` 不是等价选择

| 类型 | 语义 | 适用 |
|---|---|---|
| `RBE3` | 主节点位移 = 从节点加权平均 | 焊接/胶接的常用替代，柔性连接 |
| `CWELD` | Nastran 专用焊接单元 | 更接近真实焊点，但需要 `PWELD` 属性 |
| `CROD` | 刚性杆 | 只适合粗算，会引入虚假刚度 |

用 `RBE3` 最省事，但**必须在报告里写明这是等效处理**，不是真焊点。
真正的焊点直径、材料、失效都需要 `CWELD` + 实验数据。

### 坑 4：三层板 / 缝焊 / 胶接是三种不同问题

- **点焊**：点对点，最简单
- **缝焊**（`ADHESIVE` 41 MB 那个很可能是）：沿路径连续连接，要么建成一排 `RBE3`，要么建实体胶层
- **三层板**：一个点连三对，容易漏

不要用一个脚本套所有情况。先只做**点焊**，跑通再扩。

### 坑 5：验收标准必须是可计算的

「看起来连上了」不算。验收要能跑出数来：

| 验收项 | 判据 |
|---|---|
| 连接单元数 | = 连接清单行数（误差 0） |
| 每个连接两端都有节点 | 0 个悬空 |
| 求解器跑通 | 自由模态，**刚体模态数 = 6**（多于 6 说明还有零件没连上） |
| 最低弹性模态频率 | 与手工模型对比，差 < 15% |

**「刚体模态数 = 6」是最硬的指标。** 它是 1 行输出，但能一次抓住所有漏连。

   worker 只留一行 `[safe-delete]`，没有 traceback。写新目录 + `os.replace`。
3. **别只报成功数**。异常清单是交付的一部分，跳过一件必须能看见。连接项目同理：
   **每个没匹配上的焊点都要出现在报告里**。
4. **改完脚本必须真跑一遍最小样例**。参数名错误能通过编译，但运行时立刻崩溃。
